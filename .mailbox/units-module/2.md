## Resolutions restated as fact

1. The package and module are **`zunit`**; `zuinit` was a typo. `build.zig.zon` declares `.zunit`, `build.zig` exposes
   the module as `zunit`, and PLAN's `zunit.Volume(.mib).Dap` examples are canonical. The repository directory and
   README may be renamed to match at implementation time; that is cosmetic.
2. The public module is **dependency-free**. `Dap` speaks pure `std` types; `Siggy` declares `node` and `diag` as
   `anytype`, so a consumer that does not use siggy never wires it. dap and siggy are `build.zig.zon` dependencies of
   the private test submodule only, where both contracts are proven against the real SDKs.
3. The 2^40 volume base tag is **`tib`** (`tip` was a typo); its canonical suffix is `TiB`.
4. The volume suffix grammar is closed exactly as proposed: for prefix letter `X ∈ {K,M,G,T,P,E,Z,Y}`, accept
   `XiB | Xib | Xi | xib | xi`; reject `M`, `Mb`, `MIB`, `KIB`, `KI`, `mIB` and everything else. There is no byte
   suffix; a bare number is a plain integer byte count; the decimal point requires a suffix and at least one digit on
   each side.
5. The multiple-of-base check runs **after full evaluation**, on the final raw value: `1.5MiB` (1572864 bytes) decodes
   under `Volume(.b)` and `Volume(.kib)`, and is rejected under `Volume(.mib)`.
6. The Duration domain is **signed `i64` nanoseconds**, Go `time.Duration` parity: negative values are valid for
   Duration and only Duration; Volume remains unsigned. Zero is valid for both kinds.
7. Canonical encoding is **base-derivation**: the value in base units with the base's canonical suffix, and `.nanosecs`
   always writes an explicit `ns` — `5ns`, never a bare `5`.
8. The microsecond suffix is Go's ASCII spelling **`us`**; the earlier `mks` proposal is dead.
9. Combination components run strictly descending **h > m > s > ms > us > ns**, each unit at most once per literal,
   fraction allowed on any component.
10. The `Siggy` wrapper accepts `.literal` and `.quoted` nodes, rejects `.block`/`.tagged` with `error.UnsupportedShape`
    and a message naming the expected shape, and reports grammar and value failures with `error.Custom` plus a precise
    message in the scratch arena, leaving `diag.offset` as siggy pre-filled it.
11. dap error mapping: grammar failures → `error.InvalidWire`, value failures → `error.InvalidValue`; `value64()` fails
    with `error.UnitOverflow`.
12. Construction surface: private raw storage; checked constructors `fromBase(n)` and `fromBytes(raw)` (Volume) /
    `fromNanos(raw)` (Duration); plus `value()` and `value64()`. Nothing else in v1 — no `std.fmt` integration, no
    aliases, no additional unit kinds.
13. Layout, build and pinning as proposed: `src/root.zig` exporting only `Volume` and `Duration`, private `src/unit/`
    internals, private `src/tests/` submodule, dap v0.0.9 and siggy v0.0.1 as git-tarball url+hash dependencies,
    `minimum_zig_version = "0.17.0"`.

## Contract foundations

Restated tersely because the wrappers below lean on them; every point was verified against the local checkouts in
iteration 1 and re-checked now (dap v0.0.9 at 2abdabc, siggy v0.0.1 at 9933fec, both declaring
`minimum_zig_version = "0.17.0"`, local toolchain zig 0.17.1):

- dap's gate is presence-only: `@hasDecl(T, "decode") and @hasDecl(T, "encode") and @hasDecl(T, "deinit")` (dap
  `src/dap.zig:2855`). The operative constraints are the call sites: `decode(allocator, data)` runs inside
  `DecodeError || std.mem.Allocator.Error`, and dap's `DecodeError` is exactly
  `std.mem.Allocator.Error || error{ InvalidWire, InvalidValue }` (`src/dap.zig:605`), so our
  `error{ InvalidWire, InvalidValue }` is a subset. dap's own docs define the split: `InvalidWire` — the token is not
  the right shape; `InvalidValue` — shape is fine, value rejected.
- dap round-trips every `.direct` default through `tmp.encode(allocator)` → `T.decode(allocator, wire)` at runtime
  (`assignDirectDefault`, `src/dap.zig:2950`), and frees the wire itself. `decode` must therefore re-accept exactly what
  `encode` emits — this is what forces a sign grammar for negative durations (**U14**): once `encode` can emit `-2h`,
  `decode` must take it back. Defaults are rendered in help text through `encode` as well.
- dap calls `val.deinit(allocator)` on the value (`deinitValue`, `src/dap.zig:2911`); for one integer it is an empty
  body that must still exist.
- siggy's `isCustom` gate: `decode`'s first parameter must be exactly `*T` with at least two parameters total,
  `encode`'s first parameter `T` or `*const T` — a mutable `*T` self is not recognized on `encode` (siggy
  `src/siggy/support.zig:119`). The call is `T.decode(self_ptr, source_arena, value_arena, node, &diag)`
  (`src/siggy/schema.zig:569`); siggy pre-allocates `Self` in the value arena; `AstNode` is
  `union(enum) { literal, quoted, block, tagged }` and carries no offset — the offset arrives pre-filled in
  `diag.offset`.
- On error from a custom `decode`, siggy keeps the `diag.code` and `diag.message` we set (it substitutes
  `@errorName(err)` only when the message is empty), and surfaces `classify(diag.code)` to its caller — the identity for
  every `ParsingError` member, and both `UnsupportedShape` and `Custom` are members (`src/diagnostic.zig:6`). The
  surviving diagnostic is persisted into the value arena by siggy itself, so our message may live in scratch.
- One shared `encode(self: *const Self, allocator)` satisfies both SDKs: dap auto-refs its `var` when invoking the
  method, and siggy's by-pointer branch matches `*const T` (`src/siggy/schema.zig:764`).
- siggy resolves optionality before consulting a custom decoder: `k = { }` for `?Volume(.mib).Siggy` yields `null` and
  our `decode` never runs.

## The signed Duration rebuild

**U6** reverses iteration 1's unsigned Duration rows (`-5s` was listed there as a domain error); this section replaces
that contract, and the rest of the letter assumes it.

- **Domain.** `value()` returns `i64` nanoseconds: ±2^63 ns, roughly ±292 years — exactly Go's `time.Duration`. The
  two's-complement asymmetry carries over: `-9223372036854775808ns` (the i64 minimum) decodes, while
  `9223372036854775808ns` (+2^63 ns) overflows and is a value error.
- **Storage and pipeline.** One private `i64`. The parser accumulates component magnitudes in `u128` (checked
  multiplies, exact decimal divisions), sums them with overflow checks, checks the domain — magnitude ≤ 2^63 - 1, or
  exactly 2^63 when the literal is negative — and applies the sign last. No floating point anywhere; the same engine as
  Volume.
- **The factor check is sign-agnostic.** It runs on the signed total via remainder: `-120s` and `120s` are both whole
  counts of minutes under `Duration(.mins)`; `-90s` and `90s` are both 1.5 minutes and both rejected.
- **Encoding.** Negative values encode as `-` plus the base-derivation magnitude: a `Duration(.mins)` of -120000000000
  ns encodes as `-2m`. Zero and positives encode without a sign.
- **Constructors go signed.** `fromBase(n: i64)` — a checked `n × factor` in i128 — and `fromNanos(raw: i64)`, which
  cannot overflow because its input already is the domain, and fails only on the multiple check.
- **Volume is untouched.** Unsigned `u128` domain; no sign in the grammar, so `-5` and `+5` are stray-byte grammar
  errors; zero valid.

## Definitive grammar

**Shared scanner.** The token is consumed as exact ASCII bytes. Digits are `0-9`, leading zeros tolerated (`007` = 7). A
decimal point requires at least one digit on each side and requires a unit suffix: `1.MiB`, `.5MiB`, `1.5` and `1.h` are
all grammar errors under both kinds — one scanner, one rule. No whitespace is tolerated anywhere; any byte outside the
kind's alphabet is a stray character, so `"2 MiB"` fails in a quoted siggy value, and the non-ASCII `µ`/`μ` fail as
suffix material (**U15**). Empty input is a grammar error. Digit strings that overflow the `u128` accumulator are
rejected early — a 4096-byte siggy literal (`max_literal_len`) cannot wedge the parser. All arithmetic is exact integer
math with a `u128` mantissa and a decimal scale: `1.5MiB` is `15 × 2^20 / 10 = 1572864`, computed exactly.

**Volume.** Base tags and factors:

| tag   | factor | canonical suffix |
| ----- | ------ | ---------------- |
| `b`   | 2^0    | — (bare integer) |
| `kib` | 2^10   | `KiB`            |
| `mib` | 2^20   | `MiB`            |
| `gib` | 2^30   | `GiB`            |
| `tib` | 2^40   | `TiB`            |
| `pib` | 2^50   | `PiB`            |
| `eib` | 2^60   | `EiB`            |
| `zib` | 2^70   | `ZiB`            |
| `yib` | 2^80   | `YiB`            |

A volume literal is a magnitude — digits, or digits `.` digits — followed by an optional suffix. Without a suffix the
magnitude must be a plain integer (a dot requires a suffix) and denotes raw bytes. With a suffix, the five spellings of
the matching prefix are accepted and the value is `magnitude × 2^(10·k)`. No sign. Examples, for `Volume(.mib)` unless
stated:

## Canonical encoding

Base-derivation, with the pad's amendment: the value as a count of base units, with the base's canonical suffix, and
`.nanosecs` always writing the explicit `ns`. Every duration base now carries an explicit suffix, so canonical duration
encodings are never bare numbers; `Volume(.b)` alone encodes bare digits, since no byte suffix exists. Negative
durations prefix `-`; zero encodes as `0` with the base's suffix.

| unit                   | raw value     | encodes as |
| ---------------------- | ------------- | ---------- |
| `Volume(.mib)`         | 2097152       | `2MiB`     |
| `Volume(.b)`           | 2097152       | `2097152`  |
| `Volume(.mib)`         | 0             | `0MiB`     |
| `Duration(.mins)`      | 120000000000  | `2m`       |
| `Duration(.mins)`      | -120000000000 | `-2m`      |
| `Duration(.nanosecs)`  | 5             | `5ns`      |
| `Duration(.microsecs)` | 5000          | `5us`      |
| `Duration(.secs)`      | 0             | `0s`       |

Every canonical form re-decodes to the same value under the same base. The round-trip is not decoration: dap's default
machinery and siggy's `stringify` both depend on it, and the tests must prove it for every base, negatives included.

## The wrappers

Both wrappers hold one private raw value — `u128` for Volume, `i64` for Duration — and delegate all parsing and encoding
to the shared private base. All service methods their domain requires are present; nothing else is public.

```zig
// The namespace returned by zunit.Volume(comptime base); Siggy mirrors the same value surface.
pub const Dap = struct {
    pub fn decode(allocator: std.mem.Allocator, data: []const u8) error{ InvalidWire, InvalidValue }!Dap;
    pub fn encode(self: *const Dap, allocator: std.mem.Allocator) std.mem.Allocator.Error![]const u8;
    pub fn deinit(self: *Dap, allocator: std.mem.Allocator) void;
    pub fn value(self: Dap) u128;
    pub fn value64(self: Dap) error{ UnitOverflow }!u64;
    pub fn fromBase(n: u128) error{ UnitOverflow }!Dap;
    pub fn fromBytes(raw: u128) error{ NotMultipleOfBase }!Dap;
};

// The namespace returned by zunit.Duration(comptime base); Siggy mirrors, minus value64.
pub const Dap = struct {
    pub fn decode(allocator: std.mem.Allocator, data: []const u8) error{ InvalidWire, InvalidValue }!Dap;
    pub fn encode(self: *const Dap, allocator: std.mem.Allocator) std.mem.Allocator.Error![]const u8;
    pub fn deinit(self: *Dap, allocator: std.mem.Allocator) void;
    pub fn value(self: Dap) i64;
    pub fn fromBase(n: i64) error{ UnitOverflow }!Dap;
    pub fn fromNanos(raw: i64) error{ NotMultipleOfBase }!Dap;
};
```

```zig
// The Siggy wrapper: identical value surface, siggy-shaped service methods.
pub const Siggy = struct {
    pub fn decode(
        self: *Siggy,
        source_arena: std.mem.Allocator, // scratch: our diagnostic message lives here
        value_arena: std.mem.Allocator, // persistent; unused, the value is one integer siggy allocated
        node: anytype, // siggy.AstNode without importing siggy
        diag: anytype, // *siggy.Diagnostic without importing siggy
    ) anyerror!void;
    pub fn encode(self: *const Siggy, allocator: std.mem.Allocator) anyerror![]const u8;
};
```

**Allocation profile.** Decode paths and constructors allocate nothing — the value is one integer. The only allocations
anywhere are contractual: `encode` prints into the provided allocator (dap frees the round-trip wire itself; siggy's
arena reclaims stringify output), and a failing siggy `decode` formats its message into `source_arena`, which siggy
reclaims after persisting the surviving diagnostic.

**Error split.**

| failure class | dap error      | siggy diagnostic                   |
| ------------- | -------------- | ---------------------------------- |
| grammar       | `InvalidWire`  | `error.Custom` + message           |
| value         | `InvalidValue` | `error.Custom` + message           |
| node shape    | —              | `error.UnsupportedShape` + message |

Grammar failures are bad or unknown suffixes, stray bytes or whitespace, empty input, a misplaced or repeated sign,
wrong component order, or a suffixless component inside a combination (**U16**). Value failures are inexact decimals
(`0.5ns`, `0.0001MiB`), values that are not a multiple of the base after evaluation, and domain overflow. Node-shape
failures are siggy-only: `.block` and `.tagged` arrive with no automatic unwrapping and are refused with
`error.UnsupportedShape`.

**dap semantics.** `decode` is a static constructor that ignores the allocator; `deinit` exists with an empty body;
`encode` is called on a `var` (auto-ref) for the default round-trip and in help text. A `.direct` default authors as
`dap.defaultValue(V, V.fromBase(2) catch unreachable)` — or a negative one with `fromBase(-2)` — comptime-checked, then
round-tripped at runtime.

**siggy semantics.** `decode` accepts `.literal` and `.quoted`, running the identical grammar on the text, so
`cache = 2MiB` and `cache = "2MiB"` both decode. It fills the pre-allocated integer, and on failure sets
`diag.code`/`diag.message` and returns the same error as the code it wrote, so siggy's classification is the identity.
`encode`'s `*const Siggy` self is the one spelling both SDKs accept.

## Open questions

None of the three is blocking; each has a working proposal the rest of this letter already assumes.

- **U14 (sign closure).** The pad's **U6** answer made `Duration` signed (`value() i64`, negatives allowed), which
  supersedes iteration 1's "no sign is accepted" clause — its **U9** confirmation covered order, repeats and fractions,
  and the **U6** reversal came on top of it. A sign grammar is forced, not optional: dap round-trips every `.direct`
  default through `encode` → `decode` at runtime, so once `encode` can emit `-2h`, `decode` must re-accept it. Proposed
  closure, mirroring Go: an optional single leading sign `-` or `+` applies to the whole literal and precedes all
  components; components themselves stay unsigned magnitudes (`-1h30m` = -(1h30m); `1h-30m`, `1h+30m` and `--5s` are
  grammar errors; `-0` and `+0` decode to zero). Canonical encoding writes `-` for negative values and no sign
  otherwise. Accepting `+` is Go parity — restrict to `-` only if you prefer. Confirm or amend.
- **U15 (microsecond spellings).** The pad's **U8** answer fixed the microsecond suffix as Go's ASCII spelling `us`. Go
  itself additionally accepts two non-ASCII spellings — `µs` (U+00B5 micro sign) and `μs` (U+03BC Greek small letter mu)
  — and renders `µs` in its own `String()`. Proposed: the suffix set stays exactly the six ASCII spellings
  `ns | us | ms | s | m | h`; `µs` and `μs` are rejected as stray bytes, and `encode` emits `us`. This keeps the scanner
  single-byte ASCII (every byte is one character), dap's help text plain, and round-tripped configs unambiguous.
  Confirm, or add the non-ASCII spellings as parse-time aliases.
- **U16 (suffixless components inside combinations).** No suffix means nanoseconds, so a suffixless component is
  grammatically expressible anywhere the descending order permits it. Proposed: a suffixless component is legal only
  when it is the entire literal — `5` is 5 ns, `-30` is -30 ns — while inside a multi-component literal every component
  must carry an explicit suffix, making `1h30` a grammar error: it is almost certainly a typo for `1h30m`, and silently
  decoding it as 1 h + 30 ns would be a footgun. Zero-valued suffixed components stay fine (`0h0m` decodes to 0).
  Confirm, or allow suffixless components anywhere.
