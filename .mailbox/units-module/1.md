## What this letter does

PLAN.md is the charter: a Zig 0.17 module exposing public unit types for dap and siggy, plus a private submodule used
for testing, built around a private base type with `Dap` and `Siggy` wrappers over it. This letter grounds that charter
in the two attached SDK references and in the actual checkouts available locally (`~/Sources/mine/dap`, tag v0.0.9;
`~/Sources/mine/siggy`, tag v0.0.1; local toolchain `zig 0.17.1`), states everything the sources already settle as fact,
and anchors every remaining ambiguity as a `U` for the pad.

## Decisions already fixed by PLAN.md (restated as facts)

1. A Zig module with public unit types and a private submodule used for testing; target Zig 0.17.
2. Implementation is built around a private base type; `Dap` and `Siggy` are wrappers over that base type.
3. Access shape: `zunit.Volume(.mib).Dap` and `zunit.Duration(.secs).Siggy`. Here `UnitExpr` in PLAN's introduction is a
   placeholder for the unit expression — the result of `Volume(base)` / `Duration(base)` — and `.Dap` / `.Siggy` are
   members of that returned namespace. `Volume(base)` and `Duration(base)` are type factories; their results carry the
   two wrapper types.
4. `Volume` is parametrized by a base from `{ b, kib, mib, gib, tib, pib, eib, zib, yib }` (see **U3** for `tip`). The
   decoded raw value must be a multiple of the base unit: PLAN's own examples settle the wording — under `Volume(.mib)`,
   both `2KiB` (2048 bytes) and `4096` are rejected. (PLAN says "factor", but its examples unambiguously mean
   _multiple_.)
5. Volume parsing: `Mb` and `M` are rejected (no marketing megabytes); each binary prefix accepts the five spellings
   exemplified for kib: `KiB | Kib | Ki | kib | ki` (see **U4** for the closure of this rule); a plain number with no
   suffix is a raw value in bytes; `1.5MiB` is allowed and requires decimal arithmetic under the hood — no floating
   point anywhere, exact integer math with a mantissa and a decimal scale.
6. Volume API on both wrappers: `value() u128` (raw bytes) and `value64() !u64` (fails when the raw value exceeds u64;
   `eib` and larger bases routinely need u128).
7. `Duration` is parametrized by a base from `{ nanosecs, microsecs, millisecs, secs, mins, hours }` with the same
   multiple-of-base requirement, evaluated over the total nanoseconds.
8. Duration parsing follows Go's `time.Duration` literal conventions as amended by PLAN: no suffix means nanoseconds;
   suffixes `ns`, `mks`, `ms`, `s`, `m`, `h`; combinations concatenated from larger units to smaller ones.
9. Duration API: `value() u64` returning the total nanoseconds.

## Facts verified against the local SDK checkouts

These are observations, not proposals; the design below is built on them.

- **Toolchain.** PLAN targets 0.17 and local `zig` is 0.17.1. siggy v0.0.1 declares `minimum_zig_version = "0.17.0"`.
  The attached DAP-SDK.md says dap is for "Zig 0.16.0", but that line is stale: dap master (v0.0.9, commit 2abdabc "fix:
  0.17") declares `minimum_zig_version = "0.17.0"` and was explicitly fixed for 0.17. No real version conflict remains;
  only the pinning choice is open (**U13**).
- **dap's custom-value gate is presence-only.** `isDecodable` checks
  `@hasDecl(T, "decode") and @hasDecl(T, "encode") and @hasDecl(T, "deinit")` (dap `src/dap.zig:2855`). The operative
  constraints are the call sites:
  - `out.* = try T.decode(allocator, data)` runs inside a function whose error set is
    `DecodeError || std.mem.Allocator.Error` (dap `src/dap.zig:2887`), so a custom `decode` must return an error set
    that is a subset of `{ InvalidWire, InvalidValue }` plus allocator errors. No dap type appears in the signature —
    `dap` does not need to be imported to satisfy dap.
  - Direct defaults are routed through a runtime `tmp.encode(allocator)` → `T.decode(allocator, wire)` roundtrip (dap
    `src/dap.zig:2936`, `assignDirectDefault`), so `encode` must produce text our own `decode` re-accepts, and a
    comptime-constructible value is needed to author a `.direct` default at all (**U12**).
  - `deinit` releases a value's internals (dap `src/dap.zig:2895`, `deinitValue`); for a type holding one integer it is
    a no-op body that must still exist.
  - Custom defaults are rendered in help text through `encode`, so the encoded form is user-visible.
- **siggy's custom-leaf gate** (`siggy src/siggy/support.zig:119`, `isCustom`): a struct declaring `decode` and
  `encode`, where `decode`'s first parameter is exactly `*T` with at least two parameters total, and `encode`'s first
  parameter is exactly `T` or `*const T`.
  - The decoder calls `T.decode(self_ptr, source, value, node, &local)` where `local` is a `Diagnostic` already carrying
    the value's offset; any error set is accepted, and an unrecognized error is classified as `error.Custom` (siggy
    `src/siggy/schema.zig:561`–`579`). If our `diag.message` is empty, siggy substitutes `@errorName(err)`.
  - The encoder inspects `encode`'s first parameter and calls `T.encode(&value, alloc)` for a `*const T` self or
    `T.encode(value, alloc)` for a by-value self; a mutable `*T` self is _not_ recognized (siggy
    `src/siggy/schema.zig:765`). So one shared `encode(self: *const Self, allocator)` satisfies both SDKs: dap auto-refs
    a `var` when invoking the method, siggy's by-pointer branch matches.
  - `AstNode` is `union(enum) { literal: []const u8, quoted: []const u8, block: *Block, tagged: Tagged }` — the node
    carries no offset; the offset arrives pre-filled in `diag.offset` (siggy `src/siggy/ast.zig:6`).
  - Diagnostic messages are written into the scratch (source) allocator — siggy's own `CoresMask` example does exactly
    that — and siggy owns persistence of the surviving diagnostic.

Consequence: the `Dap` wrapper can be written entirely against `std` types, and the `Siggy` wrapper needs siggy types in
its signature only if we insist on exact typed parameters — `anytype` for `node` and `diag` passes both the gate and the
call sites. Which posture to take is **U2**.

## Module shape

The package provides exactly two public factories, `Volume` and `Duration` (package name itself is **U1 (blocking)**).
Each returns a namespace:

```zig
pub fn Volume(comptime base: VolumeBase) type   // VolumeBase = enum { b, kib, mib, gib, tib, pib, eib, zib, yib }
pub fn Duration(comptime base: DurationBase) type // DurationBase = enum { nanosecs, microsecs, millisecs, secs, mins, hours }
```

whose members are `Dap` and `Siggy` — the two wrappers over the private base type. Nothing else is public at the root.

**Dependency model (**U2 (blocking)**).** Proposal: the public module is dependency-free. The `Dap` wrapper speaks pure
`std` types; the `Siggy` wrapper declares `node` and `diag` as `anytype`. dap and siggy appear in `build.zig.zon` solely
so the private test submodule can import them as modules and prove both contracts against the real SDKs. Consumers then
never wire dap/siggy into the zunit module itself: a dap-only CLI does not drag siggy along, and vice versa. The
alternative — importing both SDKs at the root for exact typed signatures — is workable (both are small same-author
packages) but couples every consumer to both.

**Layout (**U13**).** Proposed tree:

```text
src/
  root.zig          # pub Volume, pub Duration; nothing else
  unit/
    core.zig        # literal scanner + exact decimal engine (checked u128 math, no floats)
    volume.zig      # volume base type + suffix table + Dap/Siggy wrappers
    duration.zig    # duration base type + suffix/combination engine + wrappers
  tests/            # private test submodule
    root.zig        # relatively imports ../.. internals; imports dap and siggy as modules
    core.zig, volume_dap.zig, volume_siggy.zig, duration_dap.zig, duration_siggy.zig
```

`build.zig` exposes the public module for consumers (`addModule("zunit", root src/root.zig)`, without dap/siggy imports)
and wires dap+siggy only into the `zig build test` target.

## The private base type

One generic private base per unit kind, carrying:

- the comptime `factor` of the chosen base (bytes: 1, 2^10 … 2^80; nanoseconds: 1, 10^3, 10^6, 10^9, 60·10^9,
  3600·10^9);
- the raw value (`u128` for volume, `u64` for duration);
- the parse pipeline, shared by both wrappers: scan the literal → `(mantissa: u128, scale, unit factor)` → multiply with
  overflow check → divide by 10^scale requiring exact divisibility → check the total is a multiple of the base factor →
  check it fits the raw domain.

All arithmetic is checked integer math in u128 (u64 for the duration sum's final narrowing); a decimal like `1.5MiB` is
computed as `15 × 2^20 / 10 = 1572864` exactly. Overlong digit strings (siggy literals may be up to 4096 bytes) overflow
the u128 accumulator and are rejected early rather than truncated.

## Volume

Base tags and factors:

| tag   | factor | canonical suffix                      |
| ----- | ------ | ------------------------------------- |
| `b`   | 2^0    | — (bare integer)                      |
| `kib` | 2^10   | `KiB`                                 |
| `mib` | 2^20   | `MiB`                                 |
| `gib` | 2^30   | `GiB`                                 |
| `tib` | 2^40   | `TiB` (PLAN writes `tip`, see **U3**) |
| `pib` | 2^50   | `PiB`                                 |
| `eib` | 2^60   | `EiB`                                 |
| `zib` | 2^70   | `ZiB`                                 |
| `yib` | 2^80   | `YiB`                                 |

**Grammar (**U4**).** For prefix letter `X ∈ {K,M,G,T,P,E,Z,Y}`, accepted suffixes are `XiB`, `Xib`, `Xi`, `xib`, `xi` —
first letter case-insensitive, `i` mandatory and lowercase, optional trailing `b`/`B` case-insensitive. Rejected: `M`,
`Mb`, `MIB`, `KIB`, `KI`, `mIB`, anything else. A bare number (no suffix) is raw bytes and must be a plain integer — a
decimal point requires a unit suffix, and requires at least one digit on each side of the dot.

Examples (for `Volume(.mib)` unless stated):

| input                                | verdict                                             |
| ------------------------------------ | --------------------------------------------------- |
| `2MiB`, `2Mib`, `2Mi`, `2mib`, `2mi` | ok, 2097152                                         |
| `2097152`                            | ok, 2097152                                         |
| `512KiB`, `4096`                     | error — PLAN's own examples; not a multiple of 2^20 |
| `2KiB` (under `Volume(.kib)`)        | ok, 2048                                            |
| `1.5MiB` (under `Volume(.kib)`)      | ok, 1572864 = 1536 KiB exactly                      |
| `1.5MiB` (under `Volume(.mib)`)      | error — 1.5 is not a whole count of MiB (**U5**)    |
| `0.0001MiB` (under any base)         | error — 104.8576 bytes is not a whole byte count    |
| `1.5`                                | error — decimal point without suffix                |
| `2MB`, `2M`                          | error — marketing spellings forbidden               |
| `0`                                  | ok — zero is a multiple of everything (**U6**)      |
| `-5`                                 | error — unsigned domain (**U6**)                    |

**Factor check vs decimals (**U5**).** The multiple-of-base check runs after full evaluation, on the final raw byte
count. This is the reading under which both PLAN statements hold at once: `1.5MiB` is grammatically allowed, decodes
under `Volume(.b)` and `Volume(.kib)`, and is rejected under `Volume(.mib)`.

## Duration

Base tags and factors (in nanoseconds): `nanosecs` 1, `microsecs` 10^3, `millisecs` 10^6, `secs` 10^9, `mins` 60·10^9,
`hours` 3600·10^9. Canonical suffixes for encoding: — (bare integer, ns), `mks`, `ms`, `s`, `m`, `h`.

**Suffix set (**U8**).** Exactly `ns`, `mks`, `ms`, `s`, `m`, `h`, case-sensitive. PLAN's list deliberately replaces
Go's `us`/`µs` with `mks` and does not mention the Go aliases; the proposal is to keep exactly the six. No suffix means
nanoseconds, so `5` and `5ns` are the same value.

**Combinations (**U9**).** A literal is one or more components, each `number [suffix]`, concatenated **strictly** from
larger units to smaller ones, each unit appearing at most once; a fractional part is allowed on any component, not only
the last. No sign is accepted. This is stricter than Go, which accepts any order and repeats — PLAN explicitly demands
the larger-to-smaller concatenation.

Examples (for `Duration(.secs)` unless stated):

| input                                | verdict                                              |
| ------------------------------------ | ---------------------------------------------------- |
| `500ms`                              | error — half a second is not a whole second (**U5**) |
| `1500ms` (under `.millisecs`)        | ok, 1500000000 ns                                    |
| `1h30m`                              | ok, 5400000000000 ns                                 |
| `1.5h`                               | ok, same value as `1h30m`                            |
| `2h45m10s500ms` (under `.millisecs`) | ok                                                   |
| `90s` (under `.mins`)                | error — 1.5 minutes (**U5**)                         |
| `120s` (under `.mins`)               | ok, 2 minutes exactly                                |
| `30m1h`                              | error — wrong order (**U9**)                         |
| `1m30m`                              | error — repeated unit (**U9**)                       |
| `1h30.5m`                            | ok — fraction on a non-final component (**U9**)      |
| `1.5mks` (under `.nanosecs`)         | ok, 1500 ns                                          |
| `1.5mks` (under `.microsecs`)        | error — not a whole microsecond (**U5**)             |
| `5`                                  | ok, 5 ns                                             |
| `-5s`                                | error — unsigned domain (**U6**)                     |

## The wrappers

Both wrappers hold one private raw value and are allocation-free on decode. The service methods required by each domain
delegate to the shared base.

**`Dap` wrapper (**U11** for the error mapping):**

```zig
pub const Dap = struct {
    // private raw storage
    pub fn decode(allocator: std.mem.Allocator, data: []const u8) error{ InvalidWire, InvalidValue }!Dap;
    pub fn encode(self: *const Dap, allocator: std.mem.Allocator) std.mem.Allocator.Error![]const u8;
    pub fn deinit(self: *Dap, allocator: std.mem.Allocator) void;
    pub fn value(self: Dap) u128;                                  // u64 for Duration
    pub fn value64(self: Dap) error{ UnitOverflow }!u64;           // Volume only
    pub fn fromBase(n: u128) UnitError!Dap;                        // constructors, see U12
    pub fn fromBytes(raw: u128) UnitError!Dap;                      // Volume; Duration gets fromNanos(u64)
};
```

- Grammar failures (bad suffix, stray characters, empty, `2MB`, wrong combination order) → `InvalidWire` — "the token is
  not the right shape".
- Value failures (non-integral decimal result, not a multiple of the base, domain overflow) → `InvalidValue` — "shape is
  fine, value rejected".
- `decode` allocates nothing; `encode` allocPrints into the given allocator (dap frees the roundtrip wire itself);
  `deinit` is an empty body that must exist.
- A direct default authors as, e.g. `dap.defaultValue(V, V.fromBase(2) catch unreachable)` — comptime-checked; dap then
  round-trips it through encode/decode at runtime.

**`Siggy` wrapper (**U2**, **U10**):**

```zig
pub const Siggy = struct {
    // private raw storage
    pub fn decode(self: *Siggy, source_arena: std.mem.Allocator, value_arena: std.mem.Allocator,
        node: anytype, diag: anytype) anyerror!void;
    pub fn encode(self: *const Siggy, allocator: std.mem.Allocator) anyerror![]const u8;
    // value()/value64()/constructors identical to the Dap wrapper
};
```

- Accepts `.literal` and `.quoted` nodes, running the identical grammar on the text, so `cache = 2MiB` and
  `cache = "2MiB"` both decode (**U10**).
- Rejects `.block` and `.tagged` with `diag.code = error.UnsupportedShape` and a message naming the expected shape;
  grammar and value failures set `diag.code = error.Custom` with a precise message (e.g.
  `512KiB is not a whole number of mebibytes`), leaving `diag.offset` as siggy pre-filled it, and return an error.
  Messages are allocated in `source_arena` (scratch), following siggy's own `CoresMask` pattern (**U10**).
- siggy pre-allocates `Self` in the value arena; our `decode` only fills the integer, allocating nothing (**U2** keeps
  the `anytype` posture optional).
- In configs, an optional unit field (`?Volume(.mib).Siggy`) follows normal siggy optionality: `{ }` yields `null`
  before our decoder is ever consulted.

**Canonical encoding (**U7**).** Both SDKs surface `encode` output — dap in help text and default round-trips, siggy in
`stringify`. Proposal: encode the value in base units with the base's canonical suffix, which always round-trips
exactly: `Volume(.mib)` 2097152 → `2MiB`; `Volume(.b)` 2097152 → `2097152`; `Duration(.mins)` 120000000000 → `2m`;
`Duration(.nanosecs)` 5 → `5`; `Duration(.microsecs)` 5000 → `5mks`. Alternative: always raw bytes/ns integers.

## Public API summary

| member                    | Volume wrappers                                      | Duration wrappers |
| ------------------------- | ---------------------------------------------------- | ----------------- |
| `value()`                 | `u128` (bytes)                                       | `u64` (ns)        |
| `value64()`               | `!u64`, `error.UnitOverflow`                         | —                 |
| `fromBase(n)`             | checked constructors (**U12**)                       | same              |
| `fromBytes` / `fromNanos` | checked constructors (**U12**)                       | same              |
| Dap service               | `decode` / `encode` / `deinit` per dap's contract    | same              |
| Siggy service             | `decode` / `encode` per siggy's custom-leaf contract | same              |

## Test submodule

The private `src/tests/` submodule is the only place dap and siggy are imported. It must prove:

- every accepted suffix spelling for every base, and the canonical rejections (`M`, `Mb`, `MIB`, …);
- the factor requirement, including PLAN's own `2KiB` and `4096` under `Volume(.mib)` cases and the decimal interplay of
  **U5**;
- decimal arithmetic: `1.5MiB`, `2.0KiB`, non-integral rejections, exactness;
- domain edges: zero, negatives, overflow of u128/u64, overlong literals;
- duration combinations: order, repeats, fractions on any component, `mks`;
- dap: flag and argument decode, direct-default round-trip, encode in help text, `deinit` path, both error codes
  surfaced as documented;
- siggy: literal and quoted decode, block/tagged rejection, stringify round-trip, rendered diagnostics for each failure
  class, and the value-survives-source-arena-reset discipline;
- the raw engine directly (it is private, but the tests live inside the module and import it relatively).

## Open questions

- **U1 (blocking).** The package name: the repository directory and README say `zuinit`, while PLAN.md's API examples
  all say `zunit` (`zunit.Volume(.mib).Dap`). One of the two is a typo. Proposed: `zunit` — PLAN's examples are the API
  contract consumers copy, and it reads as "zig units". The README title and repo directory can be renamed to match, or
  kept, independently. Confirm `zunit` or override with `zuinit`.
- **U2 (blocking).** Dependency posture for the public module. (a) Proposed: dependency-free — the Dap wrapper's
  `decode` uses only `std` types with error set `error{ InvalidWire, InvalidValue }` (a subset of what dap's call site
  accepts, verified against dap v0.0.9 sources), and the Siggy wrapper declares its `node` and `diag` parameters as
  `anytype` (verified to pass siggy's `isCustom` gate and both call sites). dap and siggy are zon dependencies used only
  by the private test submodule, so consumers wire neither SDK into the zunit module: a dap-only program does not pull
  siggy, and vice versa. (b) Alternative: import both SDKs at the root and write exact typed signatures
  (`node: siggy.AstNode`, `diag: *siggy.Diagnostic`); every consumer then carries both packages in its graph. Tradeoff:
  (a) is cleaner for consumers but leaves the siggy signature implicitly typed, with the contract proven by tests; (b)
  is maximally explicit at the cost of coupling. Confirm (a) or choose (b).
- **U3.** PLAN's Volume base enum contains `tip` among `b, kib, mib, gib, tip, pib, eib, zib, yib`. There is no "p" in
  "tebibyte"; this is almost certainly a typo for `tib` (2^40). Proposed: the tag is `tib`. Confirm.
- **U4.** Volume suffix grammar closure. PLAN lists `KiB | Kib | Ki | kib | ki` for kib and says "just like that" for
  the other prefixes. Proposed closure, for prefix letter `X ∈ {K,M,G,T,P,E,Z,Y}`: accepted are `XiB`, `Xib`, `Xi`,
  `xib`, `xi` (first letter case-insensitive, `i` mandatory lowercase, optional trailing `b`/`B` case-insensitive);
  everything else — `M`, `Mb`, `MIB`, `KIB`, `KI`, `mIB` — is rejected. Also proposed: there is no bare `b`/`B` bytes
  suffix (no suffix means bytes); a bare number must be a plain integer with no decimal point (`1.5` is an error while
  `1.5KiB` is fine); and a decimal point requires at least one digit on each side (`1.MiB` and `.5MiB` are errors).
  Confirm all, or amend any clause.
- **U5.** Factor-check timing versus decimals. PLAN demands both that the raw value be a multiple of the base (its
  `2KiB`/`4096`-under-`.mib` examples) and that `1.5MiB` be allowed. Proposed reading: both hold, because the
  multiple-of-base check runs after full evaluation — `1.5MiB` (1572864 bytes) decodes under `Volume(.b)` and
  `Volume(.kib)` but is rejected under `Volume(.mib)`; likewise `1500ms` decodes under `Duration(.millisecs)` but is
  rejected under `Duration(.secs)`. Additionally, a decimal whose exact value is not a whole byte (e.g. `0.0001MiB` =
  104.8576 bytes) is an error under every base. Confirm this reading.
- **U6.** Value-domain edges. Proposed: zero is valid everywhere (`0`, `0MiB`, `0s` — zero is a multiple of every base);
  negative input is rejected, since both unit kinds are unsigned (`value()` returns `u128`/`u64`); and values that
  overflow the domain (more than u128 bytes, or more than u64 nanoseconds) are reported as parse errors, never silently
  wrapped. Confirm.
- **U7.** Canonical encoding form. dap renders direct defaults through `encode` in help text and round-trips comptime
  defaults through encode+decode; siggy's `stringify` writes the encoded text into configs. Proposed canonical form: the
  value expressed in base units with the base's canonical suffix — `Volume(.mib)` 2097152 → `2MiB`; `Volume(.b)` 2097152
  → `2097152`; `Duration(.mins)` 120000000000 ns → `2m`; `Duration(.nanosecs)` 5 → `5`; `Duration(.microsecs)` 5000 →
  `5mks`. This keeps `--help` and round-tripped configs readable and always re-decodes exactly. Alternative: always emit
  the raw byte/nanosecond integer. Confirm the base-aligned suffix form.
- **U8.** Duration suffix set. Proposed: exactly `ns`, `mks`, `ms`, `s`, `m`, `h`, case-sensitive, no aliases. Go's
  `ParseDuration` additionally accepts `us` and `µs` for microseconds; PLAN's list replaces those with `mks` and does
  not mention them, and PLAN's phrase "matching ones for time.Duration from Go" refers to the literal shapes, not the
  exact suffix inventory. Confirm the six-only set, or add the Go aliases.
- **U9.** Duration combination rules. Proposed: components must appear in strictly descending unit order (h > m > s >
  ms > mks > ns), each unit at most once per literal (`30m1h` and `1m30m` are errors); a fractional part is allowed on
  any component, not only the last (`1h30.5m` and `1.5h` are both valid); no sign is accepted. Note this is stricter
  than Go, which accepts any order and repeated units; PLAN explicitly demands larger-to-smaller concatenation. Confirm
  strict-descending, no-repeats, fraction-anywhere.
- **U10.** Siggy node acceptance and diagnostics. A custom leaf's `decode` receives one of `.literal`, `.quoted`,
  `.block`, `.tagged`. Proposed: accept `.literal` and `.quoted`, running the identical grammar on the text —
  `cache = 2MiB` and `cache = "2MiB"` both decode; reject `.block` and `.tagged` (including `2MiB { }`) with
  `diag.code = error.UnsupportedShape` and a message naming the expected shape. Grammar and value failures set
  `diag.code = error.Custom` and a precise message (e.g. `512KiB is not a whole number of mebibytes`), leave
  `diag.offset` as siggy pre-filled it, and return an error; messages are allocated in the scratch `source_arena`,
  following siggy's own `CoresMask` example. Confirm, or restrict decoding to `.literal` only.
- **U11.** dap error mapping and the `value64` error. Proposed: grammar failures (bad suffix, stray characters, empty,
  wrong combination order) map to `error.InvalidWire`; value failures (non-integral decimal result, not a multiple of
  the base, domain overflow) map to `error.InvalidValue` — matching dap's documented semantics of "not the right shape"
  versus "shape is fine, value rejected". `value64()` fails with `error.UnitOverflow`. Confirm.
- **U12.** Construction and extra surface. dap's `.direct` defaults require a comptime-constructible value (dap
  round-trips it through encode+decode), and tests need to build values too. Proposed: raw storage stays private; the
  public checked constructors are `fromBase(n)` (a count of base units: `Volume(.mib).Dap.fromBase(2)`; fails only on
  overflow) and `fromBytes(u128)` / `fromNanos(u64)` (absolute values; fail when not a multiple of the base or on
  overflow); plus the planned `value()` / `value64()`. Nothing else in v1: no `std.fmt` integration, no aliases, no
  additional unit kinds. Confirm or trim.
- **U13.** Layout, build and pinning. Proposed tree: `src/root.zig` exporting exactly `Volume` and `Duration`; private
  `src/unit/core.zig` (scanner and exact decimal engine), `src/unit/volume.zig`, `src/unit/duration.zig`; private
  `src/tests/` submodule whose root imports the internals relatively and imports `dap`/`siggy` as modules, wired only
